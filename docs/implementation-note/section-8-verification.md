# 8. Verification and Test Results

## 8.1 Test Environment and Method

Testing was executed by the team on a **real multi-VM QNX deployment connected via Qnet** — environment **(C)** in `docs/test-plan/`'s own environment tagging (multiple physical/virtual QNX targets, `TRAFFIC_NODE_MAP` addressing) — following the setup procedure in `docs/QNX_DEPLOYMENT_RUN_GUIDE.md` (network/Qnet setup, binary transfer, `TRAFFIC_NODE_MAP` configuration, launch order). **231 of the 232 cases** across the seven `docs/test-plan/01-*.md` through `07-*.md` files were run by pressing the documented keys on `lx_sensor.c`/`rlx_sensor.c`/`c_operator.c`'s stdin readers on the appropriate node's VM and comparing the resulting console/log output against each case's written expected result. **All 231 cases run passed as expected.** One case, TC-TIME-05, is marked **SKIP** — same convention as `tools/test-automation/`'s own runner (never fakes a Pass for a case it can't actually drive): it requires a raw, out-of-range `offset_ms` payload that `c_operator.c`'s console cannot produce, and the `test_client` tool needed to send it directly does not exist in this repo yet (see Table 10/12).

Timing figures in Section 8.3 were derived from `central_log.txt`'s real second-resolution wall-clock timestamps (`[YYYY-MM-DD HH:MM:SS]`, written by `c_logger.c` on every persisted event) — elapsed time between two events is the timestamp difference between their log lines.

In addition to this real multi-VM execution, two static verification methods were used earlier in development and remain part of the evidence trail:
- `make check-syntax` — a host-`gcc`/`clang` `-fsyntax-only` pass over all three projects' sources (`Makefile` lines 199-223), explicitly documented as "NOT a QNX build." It catches C syntax errors, missing includes, and type mismatches, and was kept green throughout development, but it does not by itself validate QNX runtime behaviour — that validation is what the real multi-VM run above provides.
- A multi-agent spec-compliance audit conducted earlier in this project's development, cross-referencing the implemented `app/` source against `usecase.md`, `SEQUENCE_DIAGRAMS.md`, `STATE_CHARTS.md`, and `system_assumptions_tables.md`. This found and fixed several real defects by code inspection (see Table 12) *before* the full run reported here, so the run below already reflects the post-fix codebase.
